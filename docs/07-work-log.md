## 2. 다른 기기에서 이어서 작업 시작하기

### 2-1. 최초 1회 — 환경 세팅
[06 개발환경 세팅](06-dev-environment-setup.md) 참고. 요약:
1. `git clone https://github.com/BoongLee50/project_chat`
2. **Flutter**(stable) + **Android Studio**(SDK·에뮬레이터)
3. **JDK 17** 별도 설치 (⚠️ 안드로이드 스튜디오 내장 JBR은 21이라 서버 toolchain 17과 불일치)
4. **MariaDB 11.4.x** (무설치 ZIP) + DB/계정 생성 — 이름·계정·비번 모두 `moonlighttalk`
5. Gradle은 설치 불필요(`server/gradlew` 래퍼 커밋됨)

### 2-2. 매번 — 개발 시작 루틴
```bash
# ① MariaDB 기동 (재부팅하면 꺼짐)
<MariaDB>/bin/mariadbd.exe --datadir="<데이터경로>" --port=3306 --console

# ② 서버 기동 (Flyway가 스키마 자동 적용)
cd server && JAVA_HOME="<jdk17>" ./gradlew bootRun

# ③ 에뮬레이터 + 앱
flutter emulators --launch Pixel_10
flutter run -d emulator-5554
```
확인: `curl http://localhost:8080/system/gate` → `{"open":...,"nextOpenAt":"..."}`

**`git pull`로 새 커밋을 받았다면 ②를 반드시 한 번 돌릴 것** — Flyway가 새 마이그레이션을 적용한다.
**ARB(`lib/l10n/*.arb`)가 바뀐 커밋을 받았다면** `flutter gen-l10n`도 돌린다. 생성물이 저장소에 있어
안 돌리면 `undefined_getter`가 쏟아진다(함정 #28).

**⚠️ 채팅(WebSocket)을 건드릴 땐 반드시 `adb reverse` 방식으로.**
기본값 `10.0.2.2`는 에뮬레이터 NAT가 소켓을 30~60초마다 끊어서 실시간 검증이 불가능하다(함정 #12).
```bash
# 기기마다 1회 (에뮬 재시작하면 다시)
adb -s emulator-5554 reverse tcp:8080 tcp:8080
adb -s emulator-5556 reverse tcp:8080 tcp:8080

# localhost 로 붙게 빌드/실행
flutter run -d emulator-5554 --dart-define=API_BASE_URL=http://localhost:8080
```

**에뮬 2대로 채팅 테스트하기**
```bash
flutter emulators --launch Pixel_10          # 첫 번째 → emulator-5554
flutter emulators --launch Pixel_10          # 두 번째 → emulator-5556
```
- 두 기기에서 **서로 다른 소셜 버튼**으로 로그인해야 다른 계정이 된다(`dev-line` / `dev-kakao` / `dev-google`).
- 흐름: A 달빛가든에서 B에게 **대화 신청** → B 대화방에 신청 카드 → **수락** → 양쪽에 방 생성 → 채팅.
- 소켓 상태는 앱 로그로 확인: `adb -s <기기> logcat -d | grep "\[socket\]"` → `연결됨` / `AUTH_OK` / `연결 종료됨`.
- 서버 쪽은 `소켓 인증 성공` / `소켓 종료 ... status=` / `푸시 op=... 세션수=` 로그로 추적.

### 2-3. 로그인 방법 (실제 소셜 키 없음)
소셜 3사 키가 아직 없어 **개발용 목 로그인**을 쓴다.
- 서버: `application-local.yml`의 `app.auth.social.mock.enabled: true` → `MockAuthProvider`가 비활성 provider 자리를 대체.
- 클라: 소셜 버튼을 누르면 `dev-line` / `dev-kakao` / `dev-google` 토큰을 전송 → **버튼마다 다른 테스트 계정**이 된다.
- 계정 초기화하려면 DB에서 해당 `users` row 삭제(또는 DB 재생성 후 서버 재기동).

### 2-4. 낮에 개발할 때 — 게이트/배치/결제 우회
운영시간은 17~06시라 **낮에는 서버가 채팅·가든·포스트를 막는다**(서버 강제, 함정 #18).
낮에 기능을 확인하려면 게이트를 열고 띄운다.
```bash
cd server && JAVA_HOME="<jdk17>" ./gradlew bootRun --args='--app.gate.open-hour=0'
```
> `isOpen = hour >= openHour || hour < closeHour` 이므로 `open-hour=0`이면 항상 열린다.
> 실제 운영시간 동작을 볼 땐 이 옵션 없이 띄울 것.

**배치를 기다리지 않고 실행**(local 프로필에서만 열림 — `app.scheduler.dev-trigger-enabled`)
```
POST /internal/scheduler/gate-close       # 06시 종료 처리(매칭방 종료 + SYSTEM_CLOSE)
POST /internal/scheduler/daily-cleanup    # 지난 영업일 정리
POST /internal/scheduler/purge-messages   # 메시지 보관 만료 삭제
POST /internal/scheduler/expire-benefits  # 구독·엔티틀먼트·부스트 만료 정리
```

**결제 없이 상점 테스트**(`app.store.mock-purchase-enabled: true`, local 전용)
- 영수증 토큰이 **`dev-`로 시작하면 통과**한다(`MockReceiptVerifier`). 앱의 충전/구독 버튼이 이미 이 토큰을 보낸다.
- 대화 신청 무료 횟수가 소진돼 막히면: `DELETE FROM daily_usage WHERE kind='CHAT_REQUEST';`

### 2-5. 실기기(폰)에서 확인하기
에뮬레이터 기본값 `10.0.2.2`는 **실기기에서 의미가 없다**. 두 방법 중 하나를 쓴다.

**① USB + adb reverse (추천 — 방화벽·Wi-Fi 불필요)**
```bash
adb -s <폰시리얼> reverse tcp:8080 tcp:8080
flutter build apk --debug --dart-define=API_BASE_URL=http://localhost:8080
```
폰 2대를 꽂고 각각 걸면 **실기기끼리 실시간 채팅**까지 된다. IP가 바뀌어도 무관.

**② 같은 Wi-Fi + PC의 LAN IP**
```bash
flutter build apk --debug --dart-define=API_BASE_URL=http://<PC의 LAN IP>:8080
```
- 서버는 이미 `0.0.0.0:8080`에 바인딩되어 있다.
- ⚠️ **Windows 방화벽 인바운드 8080을 열어야 한다**(기본 차단). 관리자 PowerShell:
  `New-NetFirewallRule -DisplayName "달빛톡 개발서버 8080" -Direction Inbound -LocalPort 8080 -Protocol TCP -Action Allow -Profile Private`
- PC 재부팅 시 IP가 바뀔 수 있다.

> 어느 쪽이든 **PC에서 MariaDB + 서버가 떠 있어야** 한다. 실기기에서만 제대로 보이는 것: 실제 카메라 촬영, 국기 이모지 실물, 노치/둥근 모서리 레이아웃, 스크롤 체감.

### 2-6. 노트북을 들고 나갔을 때(공유기가 바뀔 때)
**대부분 문제없다.** 서버·DB·에뮬레이터가 모두 같은 노트북 안에 있어 트래픽이 밖으로 나가지 않는다.

| 연결 방식 | 공유기 영향 |
|---|---|
| 에뮬 + `10.0.2.2` | 없음 — 에뮬 내부 NAT가 호스트 루프백으로 이어준다 |
| 에뮬 + `adb reverse` | 없음 — adb 채널로 터널링 |
| 실기기 USB + `adb reverse` | 없음 — 케이블로 통신 |
| 실기기 Wi-Fi + LAN IP | ⚠️ **여기만 영향** |

앞의 셋은 **인터넷이 아예 없어도** 된다. 인터넷이 필요한 건 개발이 아니라 주변 작업이다 —
`git pull/push`, 의존성이 바뀐 뒤의 `flutter pub get`, Gradle 의존성(캐시가 따뜻하면 불필요).

**환경이 바뀔 때 실제로 걸리는 것 2가지**
1. **LAN IP가 바뀐다.** `192.168.0.x` → `192.168.1.x` 등. 실기기를 Wi-Fi로 붙이려면 매번 IP를 확인해 다시 빌드해야 한다.
2. **Windows 방화벽 프로필이 바뀐다.** 새 네트워크에 처음 붙으면 "공용/개인"을 묻는데, §2-5의 규칙은 `-Profile Private` 한정이라 **공용을 고르면 규칙이 적용되지 않는다.** "집에선 됐는데 밖에서 안 된다"의 흔한 원인.

→ **밖에서는 에뮬레이터를, 실기기가 필요하면 USB + `adb reverse`를 쓸 것.** 둘 다 네트워크와 무관하다.

> ⚠️ **DB는 기기마다 별개다.** 새 노트북에 MariaDB를 세팅하면 Flyway가 스키마는 만들지만 **데이터는 비어 있다.** 테스트 계정·포스트는 목 로그인(`dev-line` 등)으로 다시 만들어야 하며, 기기 간 데이터가 공유되지 않는다.

### 2-7. 일본어로 확인하기
기기 전체 언어를 바꿀 필요 없이 **앱 하나만** 일본어로 돌릴 수 있다(Android 13+).

```bash
adb shell cmd locale set-app-locales com.example.project_chat --locales ja-JP
```

한국어로 되돌릴 때:

```bash
adb shell cmd locale set-app-locales com.example.project_chat --locales ko-KR
```

- 앱을 **재시작**해야 반영된다(`adb shell am force-stop com.example.project_chat` 후 실행).
- `adb`가 PATH에 없으면 `%LOCALAPPDATA%\Android\Sdk\platform-toolsdb.exe`.
- **아직 안 옮긴 문구는 한국어로 남는다**(ARB에 키가 없으면 원문 폴백). 진행 상황이 눈에 보이는 셈이라
  다국어 작업 중에는 이 상태로 켜 두고 확인하면 편하다.
- 화면 확인은 `adb exec-out screencap -p > shot.png`.

### 2026-08-02(15) — 다국어 ①: l10n 뼈대 + 첫 슬라이스
**정한 것**
- **서버 메시지는 A안** — 서버는 코드만 주고 클라가 번역한다. (②단계에서 `ErrorCode` 세분화 예정)
- **언어는 기기 설정을 따른다.** 앱 안에서 고르는 설정은 아직 없다(필요해지면 `MaterialApp.locale`에 주입하면 되도록 자리만 열어 둠).

**뼈대**
- `flutter_localizations` + `intl` + `generate: true`, `l10n.yaml`(template = `app_ko.arb`, 클래스명 `L10n`).
- 원문은 **한국어**. `app_ja.arb`에 키가 없으면 한국어로 폴백되므로 번역이 덜 끝나도 앱이 안 깨진다.
- ⚠️ **지원하지 않는 언어(영어 등)가 일본어로 떨어지는 함정** — 기본 동작이 `supportedLocales.first`인데 그게 알파벳순이라 `ja`였다. 영어 기기 사용자가 일본어를 보게 된다. `localeResolutionCallback`으로 **한국어 폴백**을 못박았다(함정 #22).

**첫 슬라이스**: 로그인 + 닉네임 화면(문구 14개). 뼈대가 실제로 도는지 확인하는 용도.
- 옮기면서 걸리는 건 대부분 `const` — `const Text('...')`가 `Text(l10n.x)`가 되면서 상위 `const`를 풀고 하위에 다시 붙여야 한다. 기계적이지만 파일마다 손이 간다.
- 기존 위젯 테스트가 한국어 문자열을 직접 검사하는데, **폴백 검증 역할을 겸하게** 두고 주석으로 의도를 남겼다.

**검증**: 에뮬 앱별 언어를 일본어로 바꿔(`cmd locale set-app-locales`) 실제 전환 확인 — 옮긴 문구는 일본어, 아직 안 옮긴 문구는 한국어로 남아 진행 상황이 눈에 보인다.

**남은 규모**: 클라 462개 중 14개 완료. 서버 54개는 ②단계.

**정한 작업 방식**(이후 슬라이스에 계속 적용)
- **화면 단위로 나눠 커밋한다.** 한 번에 하면 diff가 수천 줄이라 회귀가 나도 원인을 못 찾는다.
- **치환 변수는 문자열 이어붙이기 대신 ARB placeholder로.** 일본어는 어순이 달라(`남은 3일` → `残り3日`) 조각으로 나누면 번역이 불가능해진다.
- **국기 이모지·`—` 같은 기호는 그대로 둔다.** 언어 중립이라 번역 대상이 아니다.
- **`const` 손질은 스크립트로.** `build` 본문에 `l10n` 참조가 있으면 지역변수를 넣고,
  analyze의 `invalid_constant` 위치에서 위로 올라가며 가장 가까운 `const`를 지운다.
  `const` 제거는 컴파일을 깨지 않아 반복해도 안전하다. (홈 화면에서 37개 오류가 한 번에 정리됨)
- **`build`가 아닌 메서드에도 `l10n`이 필요할 수 있다**(다이얼로그를 띄우는 `_edit` 등). 스크립트가 못 잡으므로 analyze 오류로 확인해 수동 삽입.
- **`ProfileCatalog`의 데이터 라벨(관심사 37종·지역 20곳)도 ARB에 넣는다.**
  UI 문구가 아니라 데이터 라벨이라 `InterestItem.labelJa` 필드를 더하는 선택지도 있었지만,
  **번역 자원이 두 곳으로 갈라지는 걸 막는 쪽**을 택했다. 나중에 서버 카탈로그 API로 옮기게 되면 그때 함께 이동하면 된다.

**검증**: 개방 시각을 23시로 미뤄 게이트를 닫고(`--app.gate.open-hour=23`) 확인 — 가든 안내 화면 + **"3시간 54분" 카운트다운**, 포스트 배너 + PASS 표시 유지 + 촬영 버튼 비활성, 대화방 배너, **친구 탭은 배너 없음**.

### 2026-08-02(13) — 친구 오늘의 포스트 팝업
**서버도 없었다** — `GET /friends/:id/today-post`는 01 문서에만 있고 미구현이었다.

- 응답은 피드 카드와 같은 재료(사진·하루 한마디·좋아요·댓글·PICK·접속)로 구성. 조회는 가든의 `selectPhotoKeys`·`countComments`를 재사용하고, 포스트 본문만 `FriendMapper.selectTodayPost`를 새로 만들었다(`published_at IS NOT NULL`이라 **공유한 것만** 보인다).

## 5. 미뤄 둔 기술 부채 (사용자가 늘면 드러난다)

> 지금은 사용자가 적어 **증상이 안 보인다.** 다만 원인과 해결 방향을 알아 둬야
> 나중에 "왜 이렇게 짰지"로 시간을 안 쓴다. 급하지 않지만 **출시 전에는 봐야 한다.**

### 5-1. 달빛가든 피드 — 후보 쿼리에 LIMIT이 없다

`selectFeedCandidates`가 **오늘 포스트를 올린 사람 전부**를 가져온다. 서버가 메모리에서
스코어를 매기고 정렬한 뒤 10개만 잘라 보낸다(`PAGE_SIZE = 10`).

```java
List<FeedCandidate> candidates = gardenMapper.selectFeedCandidates(...);  // ← 전부
Collections.shuffle(candidates);
candidates.sort(...);
List<FeedCandidate> page = candidates.stream().skip(offset).limit(PAGE_SIZE).toList();
```

**왜 이렇게 됐나**: Post Score에 "접속 중"이 들어가는데 그 정보가 DB가 아니라
프레즌스(인메모리/Redis)에 있다. SQL로 정렬할 수 없어 앱에서 정렬한다 — 의도된 선택이지 실수가 아니다.

**언제 문제가 되나**: 하루 활성 사용자가 수천~수만이 되면 피드 호출 한 번마다 그만큼의 행이 메모리에 올라온다.

**해결 방향(고를 것)**
- 프레즌스를 Redis로 옮기고 **접속자 id 집합을 먼저 받아** SQL에서 정렬에 반영한다(설정으로 이미 준비돼 있음)
- 또는 후보를 **최근 공유순 상위 N명(예: 300)** 으로 자르고 그 안에서 스코어를 매긴다. 정확도를 조금 포기하고 상한을 얻는 쪽

### 5-2. 달빛가든 피드 — 페이지가 어긋날 수 있다

`Collections.shuffle`을 **매 요청마다** 한다. 동점을 랜덤으로 섞기 위한 것인데,
`sort`가 안정 정렬이라 **같은 점수 그룹의 순서가 요청마다 달라진다.**

오프셋 기반 페이징(`cursor` = 건너뛸 개수)이라, 2페이지를 받을 때 1페이지와 **다른 순서** 위에서
잘라 오게 된다 → **본 카드가 또 나오거나 누군가 건너뛰어진다.**

지금은 후보가 몇 명뿐이라 안 드러나지만, 사람이 늘면 "봤던 사람이 또 나온다"로 보인다.

**해결 방향**: 셔플에 **요청 간 고정된 시드**를 쓴다. 예를 들어 `userId + sessionDate`로 시드를 만들면
같은 사람의 같은 날 조회는 항상 같은 순서가 되고, 페이징이 어긋나지 않는다.
(커서를 오프셋이 아니라 "마지막 항목의 점수+id"로 바꾸는 방법도 있지만 그건 더 큰 수술이다)
