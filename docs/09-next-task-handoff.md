## 2. 다음 작업 — Plan_3 ④단계: 댓글 개편

**왜 지금인가**: **⑤단계(달빛 한마디)의 전제**다. 달빛 한마디 댓글이 포스트 댓글과
**규칙이 같다**(3단계·50자·이미지 1장·번역). 같은 것이 확인됐으니 **한 번 만들어 두 곳에서 쓴다.**
순서를 뒤집으면 달빛 한마디에 댓글을 새로 만들고 나중에 합치게 된다([12 §6 C](12-plan3-diff.md)).

### 2-1. 지금 `post_comments`에 없는 것 🔴

```sql
CREATE TABLE post_comments (
    id, post_id, author_id,
    body VARCHAR(25),        -- ← 50자로
    created_at
);
```
**부모 참조도 이미지도 없고 본문이 25자다.** 셋 다 필요하다 → **V13**.

| 필요한 것 | 내용 |
|---|---|
| **3단계(대댓글)** | `parent_id` + 깊이 제한. 지금은 완전 평면 |
| **이미지 첨부 1장** | `image_key`(포스트 사진과 같은 업로드 흐름). 누르면 원본 팝업 |
| **본문 50자** | `VARCHAR(25)` → `VARCHAR(50)` |

> 💡 **깊이를 어떻게 막을 것인가** — `parent_id`만 두면 4단계가 만들어질 수 있다.
> `depth` 컬럼을 함께 두고 **서버가 `depth >= 3`이면 거절**하는 쪽을 권한다.
> 재귀 조회 없이 `depth`로 바로 정렬·들여쓰기가 되고, 규칙이 한 줄로 드러난다.

> 🚨 **테이블 이름을 콘텐츠 이름으로 짓지 말 것**([12 §6 E](12-plan3-diff.md)).
> ⑤단계에서 **같은 구조를 달빛 한마디에도 쓴다** — `post_comments`를 그대로 쓰든 공용 테이블로
> 빼든, **"달빛"이 들어간 이름은 피한다.** 콘텐츠 이름은 언제든 바뀐다.

### 2-2. 번역 쿼터가 이미 붙어 있다

댓글 번역은 **하루 2회 무료**(`app.translate.free-comments-per-day`)로 V7에서 이미 판정된다.
④단계에서 새로 만들 것은 없고, **화면에 번역 버튼을 붙일 자리**만 생각하면 된다
(⚠️ 번역 공급자는 아직 패스스루라 **버튼을 지금 달면 "번역했는데 원문 그대로"** 로 보인다 — [07 §6](07-work-log.md)).

### 2-3. 완료 기준

- [ ] **V13** 적용 — `parent_id`·`depth`·`image_key`, `body` 50자
- [ ] 댓글에 답글을 달 수 있고 **3단계에서 막힌다**(서버가 거절)
- [ ] 댓글에 **이미지 1장**을 붙이고, 누르면 원본이 뜬다
- [ ] 50자를 넘기면 입력이 막힌다(클라) + 서버도 거절한다
- [ ] Engage 집계(`post_stats.comments`)가 **대댓글까지 세는지** 규칙을 정하고 맞춘다
- [ ] `flutter analyze lib test` 0건 · `flutter test` 통과 · 서버 컴파일 성공
- [ ] 에뮬 2대로 **상대 화면에서 답글·이미지가 보이는지** 확인(함정 #33)

1. **기획서에 없으면 사라진 것으로 본다.** 재활용은 "비슷해 보여서"가 아니라 **규칙이 실제로 같을 때만**.
   ④→⑤가 바로 "규칙이 같음이 확인돼서" 재활용하는 경우다.

**②단계에서 얻은 것** — 숫자를 문구에 굳히지 말 것. 한도는 서버가 `field`로 싣고 ARB가 조립한다.
