## 2. 다음 작업 — Plan_3 ①단계: 게이트 폐지 + 영업일 18시

**왜 이것부터인가**: 18시 경계 위에 나머지 전부가 얹힌다.
가든 열람 제한도, 달빛 한마디도, 무료 횟수 초기화도 전부 "하루"의 정의를 먼저 알아야 한다.

### 2-1. 걷어낼 것 — 게이트

| 대상 | 위치 |
|---|---|
| 서버 판정 | `requireGateOpen()` **10곳**(chat 3 · garden 4 · post 3) + `GateService` |
| API | `/system/gate`, `GateState` |
| 클라 | `GateClosedView` · `GateBanner` · 카운트다운 · `gateProvider`/`gateOpenProvider` |
| ARB | 게이트 전용 **14키**(`gardenGateTitle`·`chatGateClosed`·`gateOpensIn`·`error*GateClosed` 등) |
| 배치 | 17시 개방 / **06시 매칭방 일괄 종료 + `SYSTEM_CLOSE`** |
| 설정 | `app.gate.open-hour` · `close-hour` |

> ⚠️ **`GateService`를 통째로 지우지 말 것.** `currentSessionDate()`·`nowKst()`가 그 안에 있고
> 영업일 계산은 **없어지는 게 아니라 기준만 바뀐다**. 게이트 판정만 걷어내고 시각 유틸은 남긴다.

> ⚠️ **06시 종료 배치가 사라지면 `chat_rooms`가 자동으로 안 닫힌다.** 매칭 방이 영구히 열려 있게 되는데,
> Plan_3에 방 종료 규칙이 따로 없다. **기획 확인이 필요할 수 있다**(신고·차단·나가기로만 닫힘).

### 2-2. 바꿀 것 — 영업일 경계 06시 → **KST 18시**

`session_date`를 쓰는 **6개 테이블**: `posts` · `daily_usage` · `feed_skips` ·
`daily_translate_targets` · `boost_activations` · `post_stats`.

- 계산 지점은 `GateService.currentSessionDate()` **한 곳**이다 — 여기만 고치면 전부 따라온다.
- **경계 시각을 설정으로 뺄 것**(`app.session.rollover-hour: 18` 같은 이름).
  게이트 설정을 지우면서 이 값이 사라지지 않게 한다.

> 🚨 **전환 규칙**: 이미 저장된 행은 옛 기준(06시)으로 찍혀 있어 **두 기준이 한 테이블에 섞인다.**
> - 지금은 **개발 DB를 비우고** 새 기준으로 시작한다(테스트 데이터뿐이다).
> - **출시 후에 경계를 또 건드릴 일이 생기면 반드시 경계 시각(18시)에 배포**한다.
>   정오에 배포하면 사용자에게 무료 횟수가 초기화된 것처럼(또는 안 된 것처럼) 보인다.
> - 자세한 설명은 [12 §6-1](12-plan3-diff.md).

### 2-3. 같이 정리되는 것 (①단계에 묶어도 되는 것)

기획서에 **없어진 게 확정**된 것들이라, 게이트를 걷어내는 김에 같이 지우는 편이 낫다.

| 대상 | 위치 |
|---|---|
| **포스트 등록 창(1시간)** | `posts.window_started_at`, `app.post.upload-window-minutes`, 홈의 "등록 남은 시간" |
| **하루 한 마디** | `posts.one_liner`, 홈 입력창, `OneLinerRequest`, ARB `homeOneLiner*` |
| **[보낸 신청] 탭** | 대화방 탭, `GET /chat/rooms/sent`, `sentStatusLabel`, ARB `chatTabSent`·`chatRequest*` |
| **스포트라이트 부스트** | `StoreKind.SPOTLIGHT_BOOST`, 상품 2종, 가든 스포트라이트 필터, 프라임 혜택, ARB |
