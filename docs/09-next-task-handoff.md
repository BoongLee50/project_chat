## 2. ⑥-B에서 얻은 것 (다음 사람이 알아야 할 것)

### 🚨 화면이 숫자를 말해야 하면 **서버가 그 숫자를 줘야 한다**

시안의 대화 신청 버튼은 `대화 신청 (무료 2회)`다. 남은 횟수를 알 방법이 없으면
개발자는 결국 **코드에 숫자를 굳힌다.** 그래서 `GET /chat-requests/quota`를 냈다 —
남은 무료 횟수 · 하루 무료 · 루나 · 글자 수 · 무제한 여부.

②단계의 *"숫자를 문구에 굳히지 말 것"* 은 **오류 문구만의 이야기가 아니었다.**
⑦단계는 온통 숫자를 다루는 단계이므로 이 원칙이 계속 걸린다.

### 🚨 혜택 목록은 **권리(엔티틀먼트)에서 나와야 한다**

프라임의 "자동 번역 무제한"이 화면에 없었다. 번역은 예전부터 프라임에게 무제한이었지만
`translate()`가 `isPrime`을 **따로** 보고 있어서, **혜택 목록에는 없는 혜택**이었다.
설정의 프라임 플랜에 `TRANSLATE_PASS`를 넣어 데이터가 곧 화면이 되게 했다.

### 메뉴 항목이 있다고 동작하는 건 아니다

채팅창 ⋯ 의 [프로필 보기]는 **오래 죽어 있었다**(핸들러 누락). 눈으로 대조하지 않으면
이런 건 영영 안 드러난다.

## 3. 다음 작업 — ⑦단계: BM·쿼터 마무리

**마지막 단계.** 새 화면은 거의 없고 **숫자와 권리**를 맞추는 일이다.

### 3-1. 🚨 번역 쿼터 — 값도, 세는 단위도 다르다

지금 `app.translate.free-comments-per-day: 2`는 **번역 건수**인데,
기획서 4-2·8-2는 *"댓글창 **5회 호출**까지 무료"* 다. **둘 다 고쳐야 한다.**

- 채팅 번역: *"동시 5개 방"* — 지금은 `free-chat-targets-per-day: 2`(하루 상대 수)
- 음성 메시지: **무료 5회**

### 3-2. `[번역 | 구매]` 버튼 (기획 4-2 이미지)

댓글·달빛 한마디 화면에 상태별로 `번역 무료` / `번역 구매` / `번역 4일`.
⚠️ **번역 공급자가 아직 패스스루다**(`app.translate.provider: none`) —
지금 붙이면 "번역했는데 원문 그대로"로 보인다. **공급자를 먼저 붙일 것.**

📌 채팅창 상단의 `[⭐ 번역|N일]` 칩은 ⑥-B에서 이미 달았다(상태 표시 + 패스 구매 진입).
여기서 할 일은 **실제 번역 동작**이다.

### 3-3. 이모지 · GIF (기획 §2-5, img11)

## 5. 작업하기 전에 꼭 읽을 것

**[12 §6](12-plan3-diff.md)의 원칙 둘**

1. **기획서에 없으면 사라진 것으로 본다.** 재활용은 **규칙이 실제로 같을 때만**.
2. 🚨 **콘텐츠 이름은 언제든 바뀐다** — **이름을 식별자로 쓰지 말 것.**

🚨 **기능이 맞다고 화면이 맞는 게 아니다.**

**단계마다 얻은 것**

- ② **숫자를 문구에 굳히지 말 것.** 한도는 서버가 `field`로 싣고 ARB가 조립한다.
- ③ 🚨 **제한은 화면이 아니라 서버가 건다.**
- ③ **삭제와 빈자리는 다르다.**
- ③ 겹쳐 놓는 **장식 레이어에는 `IgnorePointer`**(함정 #38).
- 📌 **사진을 누르는 자리는 `TappableImage`**(`shared/widgets/image_viewer.dart`).
- ⑤ **여러 조건은 한 문장으로 줄여 볼 것.**
- ⑥ **화면 상태를 목록에서 들고 오지 말 것.** 목록은 낡는다. 상세 화면은 들어올 때 서버에 묻고,
  버튼도 그 답이 정한다.
- ⑥ **우리가 지어낸 문구를 상대의 말인 척 두지 말 것.**
- ⑥-B 🚨 **화면이 숫자를 말해야 하면 서버가 그 숫자를 줘야 한다**(§2).
- ⑥-B 🚨 **혜택 목록은 권리에서 나와야 한다** — 코드가 따로 봐주는 혜택은 화면에 안 뜬다.

## 6. 개발 환경 시작

```bash
git pull origin main
```

[07](07-work-log.md) §2-2 루틴대로: MariaDB 기동 → 서버 `bootRun` → `adb reverse tcp:8080 tcp:8080` → `flutter run`.

| 잊으면 깨지는 것 | 왜 |
|---|---|
| 서버를 한 번 띄워 **V19까지 적용** | 대화 신청 200자(V19)·거절 차단(V18)·친구 한마디(V17)·마지막 접속(V16) |
| `flutter pub get` → **`flutter gen-l10n`** | ARB 생성물이 저장소에 있다(함정 #28) |
| `assets/` 폴더가 늘면 **완전 재빌드** | 번들에 안 들어간다(함정 #30) |

- **실기기**: `--dart-define=API_BASE_URL=http://localhost:8080` 필수(함정 #29)
- **에뮬 2대**: `Pixel_10` + **`Pixel_B`**(함정 #32)
- **18시 이전이면 `session_date`가 어제**다. 18시가 지나면 **가든이 빈다** —
  오늘 공유한 사람이 아직 없어서다(버그가 아니다). `scratchpad/verify_garden.py`의
  `publish_with()`로 테스트 계정을 하나 만들어 두면 편하다
- **가든/포스트 정보를 확인할 땐** 무료 계정으로 — 앨범패스·프라임은 열람 제한이 안 걸린다
- **`last_seen_at`은 소켓이 붙어야** 채워진다. REST만 두드리면 null인 게 정상이다
- **MariaDB를 내릴 땐** `mysqladmin -uroot shutdown`
