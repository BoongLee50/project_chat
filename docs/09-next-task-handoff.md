## 3. 최근에 얻은 것 (다음 사람이 알아야 할 것)

### 3-0. 대화방 종료 규칙 — 2026-09-06 구현 (B 해소)

**규칙**: 방 안에 채팅 로그가 하나도 남지 않으면 그 방은 사라진다.
메시지가 30일 뒤 사라지므로 결국 **30일간 무대화면 종료**다.

| 항목 | 확정 |
|---|---|
| 기준 | **마지막 메시지 시각(없으면 방 생성 시각)** 이 30일보다 오래되면 |
| 친구 방 | **구분 없다.** 친구 방도 30일 — `retention-days-friend`(365) 자체를 없앴다 |
| 삭제 방식 | row 삭제가 아니라 **`ENDED`** + `active_pair_key` 비우기 |
| 다시 대화 | 새 방을 만든다(`POST /chat/rooms:with/{userId}`) |
| 무료 번역 자리 | 🚨 **돌아오지 않는다.** 평생 5개 |

🚨 **"갓 만든 방"과 "로그가 다 사라진 방"은 DB에서 구분되지 않는다** — 둘 다 0건이다.
그래서 `COUNT(*) = 0`으로 찾으면 **방을 만들자마자 닫힌다.**
마지막 활동 시각을 기준으로 삼으면 기획이 말한 "처음 만들어질 때는 예외"가 규칙 안에 들어간다.

🚨 **친구 방을 닫으면 친구인데 대화를 못 걸 수 있었다.** 방을 만드는 곳이
**친구 수락 시점 하나뿐**이라, 한 번 닫히면 친구 목록의 `roomId`가 계속 비어
[대화하기]가 아무 반응도 안 했다. `ChatService.ensureFriendRoom()`을 새로 두고
[포스트 정보]의 [대화하기]가 부르게 했다. **친구가 아니면 만들지 않는다** —
모르는 사이의 방은 대화 신청 수락으로만 생겨야 신청 절차와 루나 비용을 건너뛰지 않는다.

🚨 **무료 번역 자리가 풀리고 있었다.** `countActiveTranslateRooms`가 `status='ACTIVE'`로
세고 있어 방이 닫히면 자리가 돌아왔다 — 방을 비우기만 하면 무한히 쓸 수 있었다.
방 상태를 보지 않고 **켜 둔 이력의 수**를 센다(그래서 `translate_rooms`의 행은 지우지 않는다).

**확인은 배치를 수동으로 돌려서** — `POST /internal/scheduler/purge-messages`
(메시지 삭제 → 방 종료를 **실제 잡과 같은 순서로** 부른다. 순서가 틀리면 방이 안 닫힌다).

### 3-0-B. 신청 만료·신고 차단에서 얻은 것 — 2026-09-06 (**V24**)

#### 🚨 상태값을 재활용하기 전에 **거기 붙어 있는 부수효과**를 셀 것

받은 신청 14일 만료를 `REJECTED`로 두려다 멈췄다. 거절에는 **1일 재신청 금지**(V18)가 딸려 있어서,
**내가 답을 안 했을 뿐인데 상대가 다시 신청도 못 하게 된다.** 이름이 비슷하다고 뜻이 같지 않다 —
`EXPIRED`를 새로 만들었다.

#### 같은 규칙이라도 **표의 유니크 제약**이 처리를 가른다

| | 대화 신청 | 친구 신청 |
|---|---|---|
| 만료 처리 | `status='EXPIRED'`(행 유지) | **행 삭제** |
| 왜 | 목록이 전부 `PENDING` 조회라 상태만 바꿔도 사라진다 | `pair_key`가 UNIQUE — 남기면 **다시 신청 못 한다** |

#### 🚨 **캐시해 둔 순서로 그린다면, 그리는 시점에도 자격을 다시 볼 것**

달빛가든이 차단을 **후보 산정 질의**에서만 걸렀다. 순서는 진입 시 한 번 정해지고 스크롤은 전부
`selectCandidatesByIds`를 타는데 거기엔 조건이 없어서, **차단당한 쪽 화면에 차단한 사람이
계속 나왔다.** 옛 주석은 *"한 세션이면 지나간다"* 며 의식적으로 넘긴 것이었는데,
차단은 잠시 뒤에 반영되면 되는 일이 아니다.

#### 목록에서 빼는 것으로는 부족하다 — **상세도 막아야 한다**

낡은 목록·이미 떠 있는 화면이 상세로 들어오는 통로가 된다. [포스트 정보]는 409로 막는다.

#### 📌 고친 뒤에는 **되돌려서 실패하는지** 볼 것

고친 코드로 통과해도 원래 통과했을 수 있다. 매퍼만 되돌려 서버를 다시 띄우고 **2페이지에
그대로 나오는 것**을 눈으로 본 뒤 복구했다. 이 왕복이 없으면 "고쳤다고 믿는다"가 된다.

### 3-0-E. 대화방 UI 개편 — 2026-09-19 (**V26**)

**신뢰 순서가 정해졌다 — 기획사항 > 기획서 > 이미지.** 모순이 난 자리마다 이 순서로 골랐다

*"뒤로가기 말고는 대화방에는 화살표가 없음!"* 그래서 `icon_next`는 **에셋으로 들이지도 않았다.**

- **셀 = 2열 카드**(`frame_list` 504×522). 사진은 **프로필 사진**, 글은 **25자 + `…`**,
  시각은 분·시간·일(**30일 넘으면 안 보임**), `ON`은 접속 중일 때만, `N`은 미확인일 때만.
- 🚨 **미리보기는 마지막 "글", 시각은 마지막 "메시지"** — 음성이 마지막이면 글은 그 전 것, 시각은 음성 것.
- **받은 신청의 `N` = 아직 안 열어 본 신청**(V26 `viewed_at`) — "대화 목록과 기능 동일"에서 옮겼다.
  **받는 사람이 열 때만** 찍힌다(보낸 사람이 열어도 안 찍힘 — 검증함).
- 🚨 **셀을 누르면 확인창 없이 바로 채팅창**이다. 기획서 260919 6-1의 *"대화방으로 이동할까요?"* 는
  **안 하기로 했고 기획서에서도 지워질 문장**이다 — 기획서를 다시 읽고 되살리지 말 것.
- 🚨 **받은 신청 팝업은 스크롤하지 않는다.** 시안대로 쌓으면 짧은 폰에서 몇 픽셀 넘쳐 "울렁"거렸다 —

- **받은 신청 팝업**: `[대화하기]` = 수락 + **새 채팅창 바로 열기**. 번역은 **무조건 무료**(scope `REQUEST`).
  `[원문보기]`는 번역문이 원문과 다를 때만 보인다 → 🚨 **개발 중엔 안 보인다**(`provider: none`).
  보려면 `APP_TRANSLATE_PROVIDER=mock`으로 서버를 띄울 것(PowerShell `$env:` → Start-Process가 물려받는다).

🚨 **신청 한마디 100자는 코드포인트로 센다 — Flutter `maxLength`를 쓰지 말 것**(함정 #82).
`maxLength`는 `👍🏽`를 1로 세서 서버·DB와 어긋난다. 두 팝업은 `shared/widgets/request_message_input.dart`를 쓴다.

**포스트 화면이 스크롤되려 했다** — 카드 높이를 남은 높이로 계산해 **한 화면에 정확히
들어차는데** `AlwaysScrollableScrollPhysics`가 남아 있어, 끌면 화면 전체가 늘어났다
(안드로이드 12+ stretch). `NeverScrollableScrollPhysics`로 막았고 **이 화면의 당겨서
새로고침은 사라졌다**(함정 #79).

**🚨 "비어 있는 창"이 사실은 빈 목록이 아니었다** — 사용자가 본 것은 빈 상태가 아니라
**사진 0장인 카드**였다. 후보 조건이 `published_at IS NOT NULL` 하나뿐이라,
**공유한 뒤 사진을 다 지운 사람**이 검은 칸으로 남는다(`deletePhoto()`는 published를 안 지운다).
실사용자도 닿는 경로다. `EXISTS (post_photos)`를 **두 쿼리 모두**에 넣었다(함정 #80, #58).

📌 **증상을 그대로 믿지 말 것.** "빈 화면"이라고 들었지만 API는 항목 17개를 주고 있었다 —
**화면이 비어 보이는 것과 목록이 빈 것은 다른 일**이고, 고칠 곳도 달랐다.

⚠️ 그 17개를 만든 것은 **우리 검증 스크립트**였다(`publish_post()`가 사진 행을 안 넣었다).
스크립트는 DB에 직접 쓰므로 **서버가 막는 조건을 그냥 통과한다**(함정 #81). 고치고 지웠다.

**빈 목록일 때는 배경만 남긴다 — 빈 상태 화면은 만들지 않기로 확정됐다**(기획 2026-09-19).
기획서에 빈 상태가 **처음부터 없고**(4-1은 *"풀이 소진되면 다시 반복하여 출력"*),
🤖 **빈 자리는 봇 데이터가 채울 예정**이기 때문이다 — **§4-1**.
문구도 그림도 요청하지 않았다. ⚠️ 그래서 **봇이 무산되면 이 결정부터 되돌려야 한다.**

📌 내가 걷어낸 `gardenEmptyTitle`/`Detail`은 **기획서에 없는, 우리가 지어낸 문구**였다
(다국어 작업 때 화면을 채우려고 만든 것). ARB에는 남겨 뒀다 — 봇이 늦어지면 되살리면 된다.

`app.garden.boost.priority-viewers`(기본 3). ⚠️ **이 값은 체감상 거의 즉시 사라진다** —
서버는 카드를 목록에 실어 보낸 것까지만 알고 스크롤 여부는 모르기 때문이다.

### 3-3. ⑦단계에서 얻은 것

### 🚨 값이 아니라 **"무엇을 세는가"** 를 먼저 볼 것

무료 번역이 기획서와 달랐는데, **숫자만 다른 게 아니었다.**

| 자리 | 기획서 | ⑦ 전 |
|---|---|---|
| 댓글창 | "댓글창 **5회 호출**" | 번역 **건수** 2 |
| 대화방 | "**5개까지**, 삭제 전까지" | 하루 **상대 수** 2 |

`2 → 5`만 고쳤다면 여전히 틀렸다. 댓글은 **창**이 단위라 창 하나에 댓글이 열 개여도
자리는 하나다. 대화방은 날짜가 아니라 **동시에 열어 둔 방의 수**다.

### 🚨 못 주는 것은 **받지도 말 것**

번역 공급자가 없으면 자리를 쓰지 않는다. 기능이 준비되지 않았을 때
**아무것도 소모하지 않는 것**이 옳은 기본값이다.

### 기획서가 허락한 삭제는 삭제해도 된다

GIF는 *"문제 있을 경우 **해당 기능 삭제**"* 라고 적혀 있었다. 키 없이 죽은 버튼을
남기는 것보다 낫다.

### 🐛 COALESCE는 **바깥**에

`SELECT COALESCE(likes, 0) FROM post_stats WHERE ...` — 컬럼 NULL만 막고
**행이 없으면** 0행 → null → int로 받다가 터진다. `SELECT COALESCE((SELECT ...), 0)`.
통계 행은 첫 노출 때 생기므로 **공유 직후에는 늘 없는 상태**다.

### 4-1. 🤖 봇 데이터 — **예고된 기능**(기획 2026-09-19)

> *"추후 봇 데이터를 넣어서 만약 유저가 없다면 봇 데이터를 출력하게 할 것."*

**지금 당장 만들 것은 없다.** 다만 **이미 내린 결정 하나가 여기에 묶여 있다** —
달빛가든의 **빈 상태 화면을 만들지 않기로 한 것**(안내 문구도 그림도 요청하지 않았다)이
*"어차피 봇이 채운다"* 를 전제로 한 결정이다. 봇이 무산되면 **그 결정부터 다시 봐야 한다.**

🚨 **설계를 시작하기 전에 정해야 할 것들** — 나중에 정하면 비싸진다.

| # | 정해야 할 것 | 왜 나중이면 비싼가 |
|---|---|---|
| 1 | **봇을 무엇으로 구별하나** (`users`에 칼럼? 별도 표?) | 🔴 DB. 이게 없으면 아래가 **전부** 불가능하다 |
| 2 | 봇에게 **대화 신청·친구 신청**이 가는가 | 답이 없으면 14일 뒤 만료로 사라진다 — 그 사이 **루나는 이미 나갔다**. 막을 거면 신청 경로에서 걸러야 한다 |
| 3 | 봇을 **신고·차단**할 수 있나 | 차단은 `blocks`에 행이 남는다. 봇이 갈리면 정리 대상이 된다 |
| 4 | 봇이 **통계에 섞이나** (`post_stats`의 노출·좋아요·전환율) | 섞이면 Engage 점수와 부스트 효과 측정이 오염된다 |
| 5 | 봇이 **온라인으로 뜨나** (`presence`·`last_seen_at`) | 프레즌스는 소켓이 붙어야 갱신된다 — 봇은 소켓이 없다 |
| 6 | **"유저가 없다"의 판정 기준** — 0명인가, N명 미만인가 | 아래 참고 |

📌 **구현할 때 알아야 할 것 셋** (지금 구조에서 이미 정해져 있는 것들)

- **봇도 실제 표를 타야 한다.** 피드 후보 조건은 `posts.published_at IS NOT NULL` +
  **`EXISTS (post_photos)`** + `users.status='ACTIVE'` + 차단·신고 제외다.
  봇용 별도 경로를 만들면 **조건이 두 벌이 되어 한쪽만 늙는다**(함정 #58이 정확히 그 사고였다).
  `users` · `posts` · `post_photos` 행을 실제로 넣는 쪽이 안전하다.
- 🚨 **매 영업일 다시 만들어야 한다.** 후보 조건이 `session_date = 오늘`이고,
  18:05 배치가 **지난 영업일 사진을 지운다.** 즉 봇 포스트는 **영업일마다 새로 생성하는 배치**가
  필요하다 — 한 번 넣어 두면 하루 뒤에 사라진다.
- **섞는 자리는 순서를 산정하는 한 곳이다**(`GardenService`의 후보 조회 직후, 6:4 믹싱 전).
  ⚠️ 순서는 **진입할 때 한 번** 정해지고 30분 유지되므로(`FeedSessionStore`),
  "유저가 없다"의 판정도 그 시점 한 번이다 — 보는 중에 실유저가 들어와도 그 세션에는 안 보인다.

⚠️ **개발 중에는 가든이 자주 비어 보인다.** 봇이 들어오기 전까지는 정상이다 —
영업일 경계가 18시라 그 전에는 "오늘 공유한 사람"이 없을 수 있다([07 §2-4](07-work-log.md)).

1. **기획서에 없으면 사라진 것으로 본다.** 재활용은 **규칙이 실제로 같을 때만**.
2. 🚨 **콘텐츠 이름은 언제든 바뀐다** — **이름을 식별자로 쓰지 말 것.**

**단계마다 얻은 것**

- ② **숫자를 문구에 굳히지 말 것.** 한도는 서버가 `field`로 싣고 ARB가 조립한다.
- ③ 🚨 **제한은 화면이 아니라 서버가 건다.**
- ③ **삭제와 빈자리는 다르다.**
- ③ 겹쳐 놓는 **장식 레이어에는 `IgnorePointer`**(함정 #38).
- 📌 **사진을 누르는 자리는 `TappableImage`**(`shared/widgets/image_viewer.dart`).
- ⑤ **여러 조건은 한 문장으로 줄여 볼 것.**
- ⑥ **화면 상태를 목록에서 들고 오지 말 것.** 목록은 낡는다.
- ⑥ **우리가 지어낸 문구를 상대의 말인 척 두지 말 것.**
- ⑥-B 🚨 **화면이 숫자를 말해야 하면 서버가 그 숫자를 줘야 한다.**
- ⑥-B 🚨 **혜택 목록은 권리에서 나와야 한다** — 코드가 따로 봐주는 혜택은 화면에 안 뜬다.
- ⑦ 🚨 **값이 아니라 "무엇을 세는가"를 먼저 볼 것**(§3).
- ⑦ 🚨 **못 주는 것은 받지도 말 것**(§3).
- 🚨 **상태값을 재활용하기 전에 부수효과를 셀 것**(§3-0-B).
- 🚨 **캐시해 둔 순서로 그린다면 그리는 시점에도 자격을 다시 볼 것**(§3-0-B).
- 📌 **고친 뒤에는 되돌려서 실패하는지 볼 것**(§3-0-B).

## 6. 개발 환경 시작

```bash
git pull origin main
```

[07](07-work-log.md) §2-2 루틴대로: MariaDB 기동 → 서버 `bootRun` → `adb reverse tcp:8080 tcp:8080` → `flutter run`.

| 잊으면 깨지는 것 | 왜 |
|---|---|
| 서버를 한 번 띄워 **V26까지 적용** | 신청 만료 EXPIRED(V24)·대화 신청 150자(V25)·**신청 한마디 100자 통일 + 받은 신청 열람(V26)** |
| ⚠️ 대화방 종료 규칙(30일) | 30일 무대화 방이 배치에서 ENDED가 된다. 오래된 개발 데이터가 한 번에 닫힐 수 있다 |
| ⚠️ **받은 신청 만료 규칙(14일)** | 14일 넘게 답하지 않은 신청이 `expire-requests` 한 번에 전부 사라진다. **배치는 내 계정만 보지 않는다** |
| `flutter pub get` → **`flutter gen-l10n`** | ARB 생성물이 저장소에 있다(함정 #28) |
| `assets/` 폴더가 늘면 **완전 재빌드** | 번들에 안 들어간다(함정 #30) |

- **실기기**: `--dart-define=API_BASE_URL=http://localhost:8080` 필수(함정 #29)
- **에뮬 2대**: `Pixel_10` + **`Pixel_B`**(함정 #32)
- 📌 **검증 스크립트가 이제 저장소에 있다 — [`tools/`](../tools/README.md).**
  ```bash
  python tools/verify/verify_moderation.py        # 신청 만료 · 신고/차단 정리 범위
  python tools/verify/verify_feed_block_page2.py  # 차단이 캐시된 순서에도 먹는가
  python tools/spec/diff_docx_text.py "<옛 기획서>" "<새 기획서>"
  ```
  `_common.py`의 `login()`·`publish_post()`·`clear_ties()`로 **새 검증도 몇 줄이면 쓴다.**
  (예전엔 `scratchpad/`에 두고 커밋하지 않아 다른 기기에서는 **문서만 있고 실물이 없었다.**)
- **18시가 지나면 가든이 빈다** — 오늘 공유한 사람이 아직 없어서다(버그가 아니다).
  `publish_post()`가 하는 일이 이것이고, 직접 하려면 이렇다:
  ```sql
  INSERT INTO posts (id, user_id, session_date, published_at, content_updated_at)
  VALUES ('p-x', '<userId>', '<영업일>', NOW(), NOW())
  ON DUPLICATE KEY UPDATE published_at = NOW(), content_updated_at = NOW();
  ```
  본인은 후보에서 빠지고, **15분 안에 이미 본 상대도 빠진다** —
  다시 보려면 `DELETE FROM feed_exposures WHERE user_id='<보는 사람>';`
- **번역 흐름을 보려면** `./gradlew bootRun --args='--app.translate.provider=mock'`
  (⚠️ 운영 금지 — 번역하지 않고 `〔ja〕` 표시만 붙인다)
- **가든/포스트 정보를 확인할 땐** 무료 계정으로 — 앨범패스·프라임은 열람 제한이 안 걸린다
- **`last_seen_at`은 소켓이 붙어야** 채워진다. REST만 두드리면 null인 게 정상이다
- **MariaDB를 내릴 땐** `mysqladmin -uroot shutdown`
