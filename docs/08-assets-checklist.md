### 🧭 리소스가 오기 전까지 UI를 만드는 방식 (2026-08-29 확인)

**UI 리소스는 기획/디자인 쪽에서 추후 별도로 전달된다.** 그때까지 이쪽에서 하는 일은 이렇다.

| 하는 것 | 안 하는 것 |
|---|---|
| 새 UI는 **코드로 그린다** — Flutter 위젯 + 테마 토큰(`AppColors`/`AppDimens`) + Material 기본 아이콘 | **이미지를 만들거나 어디서 따오지 않는다.** 캡처·생성·크롭 전부 해당 없음 |
| 전달받은 리소스가 있는 자리만 `ArtImage`로 그림을 쓴다 | 시안 없이 이미지를 임의로 채워 넣지 않는다 |

**왜 코드로 그리나** — 리소스가 오면 **그 자리만 갈아끼우면 되도록** 하기 위해서다.
색·여백·모서리를 테마 토큰으로 잡아 두면 그림으로 바뀔 때 레이아웃을 다시 짤 일이 없다.
반대로 임의 이미지를 채워 두면 최종본이 왔을 때 규격이 어긋나 두 번 일하게 된다.

> ⚠️ **얇은 선·단순 도형·라운드 사각은 앞으로도 이미지로 받지 말 것.**
> 늘리면 선 굵기와 곡률이 찌그러지고 번진다([07](07-work-log.md) 함정 #31).
> 실제로 `포스트 사진 외곽선.png`를 받았다가 쓰지 않고 `Border.all`로 코드로 그렸다.

### 🚨 이 앱의 UI 언어는 **두 종류**다 (2026-08-08 확정)

리소스를 다룰 때 이것부터 알고 시작해야 한다.

| 종류 | 무엇 | 언어 전환 |
|---|---|---|
| **폰트** | ARB(`app_ko.arb`/`app_ja.arb`)가 그리는 글자 | 기기 언어를 따라 자동으로 바뀐다 |
| **이미지** | 그림에 글자가 **구워져 있는 것**(필터 칩, 타이틀, 로그인 배경…) | **바뀌지 않는다 → 일본어판 이미지를 따로 받아 교체** |

**이미지 속 한글은 "덜 옮긴 것"이 아니라 의도된 상태다.** 폰트로 대체하려 들지 말 것.
일본어판은 **같은 규격의 일본어 이미지**를 받아 교체한다(같은 파일명 / `ja/` 폴더 등).
규격만 같으면 코드를 안 고쳐도 되도록 `ArtImage`가 원본 크기를 상수로 들고 있다 —
**기획에 요청할 때 "같은 규격으로"를 반드시 명시할 것.**

> 📌 **일본어판 이미지 목록 작성이 ③단계의 선행 작업이다.**
> `assets/images/` 전체를 훑어 글자가 있는 파일을 추리면 된다. 달빛가든 쪽은
> `lib/features/garden/presentation/widgets/garden_art.dart`의 상수 목록이 그대로 목록이 된다.

### 1-1. 배경 1080×2640 — 어디가 잘리고 어디가 가려지나

원본이 **22:9**라 흔한 폰(19.5~20:9)보다 길다. **잘리는 것**과 **시스템 UI에 가려지는 것**은
**서로 다른 층**이니 나눠서 본다. (코드 확인: `login_screen.dart` · `onboarding_scaffold.dart`)

**① 잘림 — 위가 아니라 아래만 잘린다**

```dart
Image.asset(..., fit: BoxFit.cover, alignment: Alignment.topCenter)
```
`topCenter`라 **위를 붙박아두고 남는 만큼 아래에서만** 잘라낸다(기본값 `center`가 아니다).
원본 폭 1080이 화면 폭과 같아 배율이 정확히 **1.0** — 화면 픽셀 = 이미지 픽셀이라 계산이 단순하다.

| 기기 | 잘리는 곳 |
|---|---|
| 1080×2400 (20:9) | 아래 **240px** |
| 1080×2340 (19.5:9) | 아래 **300px** |
| 1080×2160 (18:9, 구형) | 아래 **480px** |

**위쪽은 한 픽셀도 잘리지 않는다.**

**② 가려짐(세이프 에리어) — 잘림과 별개다**

배경은 `SafeArea` **밖**에 두어 화면 끝까지 그린다(콘텐츠만 SafeArea 안). 잘리진 않지만 **덮인다.**

| 구역 | 크기(1080 기준) | 무엇이 덮나 |
|---|---|---|
| 상단 | 약 **72~144px** | 상태바(시계·배터리) + **카메라 펀치홀** |
| 하단 | 약 **72px**(제스처) / **144px**(3버튼) | 내비게이션 바 |

**→ 디자이너에게 전할 것**

- **위 약 150px** — 잘리진 않지만 상태바·카메라홀에 걸린다. **로고·달 같은 주요 요소는 그 아래로.**
- **아래 약 500px** — **잘려 없어질 수 있다**(구형 18:9 기준). 여기엔 중요한 것을 두지 말 것.
- 로그인 화면은 하단에 **어두워지는 그라데이션**(`AppColors.nightScrim`)이 덮이므로
  아래쪽 디테일은 어차피 거의 보이지 않는다. **화면 상단~중앙에 승부를 걸 것.**

## 5. 결정이 필요한 것

| 항목 | 선택지 |
|---|---|
| 기능 아이콘 | Material 기본 유지 vs 커스텀 아이콘셋 제작(하단 5탭 + 화면 내 아이콘 약 30종) |
| 국기 표시 | 이모지 유지(무료·간단, 기기마다 모양 다름) vs 이미지(일관됨, KR/JP 2장이면 충분) |
| 폰트 | 시스템 기본 vs 커스텀(한·일 동시 지원 필요 — Noto Sans KR/JP 등) |
| 이미지 포맷 | JPG/PNG vs WebP(용량 30~50% 절감, 안드·iOS 모두 지원) |

## 6. 넣는 방법 (참고)

```
assets/images/        # 앱 내 이미지 — pubspec.yaml에 폴더째 등록돼 있어 파일만 넣으면 된다
```
- `pubspec.yaml`의 `assets: - assets/images/` 는 이미 설정됨. **개별 파일 등록 불필요.**
- 앱 아이콘·스플래시는 패키지 도입 후 `flutter pub run` 한 번으로 생성.
- 사용자가 올리는 사진(프로필·포스트)은 여기가 아니라 **서버 스토리지**로 간다(02 문서 §3).
