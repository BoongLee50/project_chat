**"주로 볼 그래픽"은 출발점이지 울타리가 아니다.** 화면은 다른 콘텐츠의 그림을 빌려 쓴다:

- **하단 주메뉴 그림은 전부 `달빛가든 화면`에 있다**(`menu_*`, `main_menu_icon_friend_*`) — 모든 탭 화면이 쓴다
- **상단 `Prime` 버튼**(`button_prime`)도 `달빛가든 화면` 것을 쓴다(다른 화면 폴더에도 같은 이름이 따라온다) — 공용 `ArtTopBar`. 🗑 `루나` 버튼은 2026-11-14 없어졌다(기획서 261111 — 루나 폐지)
- **친구 `[받은 신청]` 탭은 `대화방 화면`의 그림을 쓴다**(바이트까지 같아 한 벌만 들였다)
- 국기·`ON` 같은 작은 그림은 콘텐츠마다 비슷한 것이 따로 오기도 한다 — 이름이 같아도 **규격을 확인**할 것
- 🚨 **시안(참고 화면)은 `Example/` 폴더 없이 리소스와 같은 폴더에 섞여 온다**(사용자 2026-11-14 · 2026-11-15 다시 확인, 프로젝트 전체).
  **파일명이 한글**(`…_좌표값.png`·`… 참고화면.png`·`화면 확인 샘플.png` 등)이고 **UI 한 조각이 아니라 화면 전체가 완성된 모습**(대개 1080×2640)이면 **시안 = 참고 화면이지 리소스가 아니다.**
  ⚠️ **폴더 이름이 한글인 것은 상관없다** — `그래픽 소스` 아래는 폴더가 전부 한글이다. 판단은 **파일 이름**으로 한다.
  2026-11-15 `그래픽 소스` 전체에서 한글 파일명 103장은 **모두** 좌표값·참고화면·샘플이었다(실제 리소스 중 한글 이름은 0장).
  시안은 앱에 넣지 않고 좌표·배치 참고로만 본다. 영문 이름(`button_*`·`frame_*`·`icon_*`·`title_*`·`back_*`)은 실제 리소스 — `back_*`처럼 1080×2640 배경도 있으니 크기만으로 판단하지 말 것.
  (예전 전달본의 `Example/` 폴더도 시안이다)

## 2. 시작할 때 (명령을 받으면 이 순서로)

1. `git pull --ff-only origin main` — 다른 기기 커밋이 있으면 [두 기기 절차](../docs/07-work-log.md)대로(서버 기동 → 마이그레이션 적용, `gen-l10n`)
2. [`docs/07`](../docs/07-work-log.md) §1(현재 상태) → [`docs/09`](../docs/09-next-task-handoff.md) **머리 + §0 표의 내 줄**
3. **UI를 건드릴 거면** [`docs/14`](../docs/14-ui-ground-rules.md) UI 대전제를 먼저 — 언어는 한·일 둘, 글자가 박힌 그림은 그림째 바뀐다, **아이콘·버튼도 그림이다**(`Icons.*`는 자리 표시)
4. 내 UI 폴더를 실제로 열어 본다. 새 전달본인지는
   `python tools/spec/compare_ui_delivery.py "D:/Plan_Chat/그래픽 소스"` 로 — 결과 중 **내 화면 폴더 줄**을 본다(시안은 도구가 알아서 건너뛴다)
5. 사용자에게 **세 줄 이내로** 보고: 지금 상태 · 내 콘텐츠의 다음 할 일(09 §0) · 전달본 변화 유무

## 4. 🚨 동시 작업 규칙 — 여섯 세션이 한 저장소를 쓴다

1. **내 콘텐츠 파일만 고친다.** 아래 **공용 파일**을 고쳐야 하면 최소한으로 하고, 끝에 보고할 때
   *"공용 파일 ○○를 고쳤다 — △△ 화면도 함께 바뀐다"* 를 꼭 적는다.

   | 공용 파일 | 누가 같이 쓰나 |
   |---|---|
   | `lib/shared/widgets/*`(`design_canvas.dart`·`art_top_bar.dart`·`main_bottom_nav.dart` 등), `lib/core/*` | 전부 |
   | `lib/features/chat/presentation/widgets/talk_cell.dart`·`request_popup.dart` | **대화방·친구**(셀 · 팝업 세 개가 한 벌) |
   | `lib/features/chat/` 의 `chat_provider` · `chat_api` · `chat_models` · 서버 `chat/` | **대화방·채팅창**(목록·신청 ↔ 메시지·소켓) |
   | `shared/widgets/art_top_bar.dart`([Prime] 문) · `shared/widgets/translate_pass_button.dart`([번역] 문) | 전부 ↔ **상점** |
   | `lib/features/chat/presentation/widgets/chat_request_dialog.dart` | 대화방·가든(4-3 대화 신청) |
   | `lib/features/garden/presentation/widgets/comments_sheet.dart` · 서버 `comment/` | **가든·달빛 한마디**(포스트 댓글과 한마디 댓글이 한 벌) |
   | `lib/features/postinfo/*`(`profile_view_screen.dart`·`post_info_provider.dart`) | 가든·대화방·친구·프로필 |
   | `lib/shared/widgets/request_message_input.dart`(신청 한마디 100자) | 대화방·친구 |
   | `pubspec.yaml` · `lib/l10n/*.arb`(+생성물) · `server/.../common/*` · `application.yml` | 전부 |

2. **커밋은 경로를 집어서 내 파일만.** `git add <파일들>` → `git commit`.
   🚫 `git add -A` · `git add .` · `git commit -a` · `git stash` · `git checkout -- .` · `git reset --hard` 금지 —
   같은 폴더의 **다른 세션이 쓰다 만 변경을 쓸어 담거나 지운다.**
   `git status`에 내가 만들지 않은 변경이 보이면 **손대지 않는다**(다른 세션 것이다).
3. **Flyway 번호는 경쟁이다.** 새 마이그레이션을 만들기 **직전에**
   `ls server/src/main/resources/db/migration | sort -V | tail -3`으로 최신 번호를 보고, 만들면 **바로 커밋**한다.
   같은 번호가 둘이면 서버가 아예 안 뜨고 **여섯 세션이 다 멈춘다.** 문서의 함정 번호(`docs/07` §3 `#NN`)도 같다.
4. **ARB 키는 그 화면의 기존 접두어를 따른다** — 포스트 `home*` · 가든 `garden*` · 대화방 `chat*` ·
   친구 `friend*` · 프로필 `profile*`/`interest*` · 달빛 한마디 `daily*` · 채팅창 `chat*`(대화방과 같은 접두어 — 목록은 `chatRooms*`) · 상점 `prime*`·`store*`·`boost*`·`pass*`·`luna*`. **ko·ja 둘 다** 넣고 `flutter gen-l10n` 생성물도 함께 커밋.
5. **서버(8080)와 폰은 하나다.** 서버를 다시 띄우면 다른 세션의 검증이 끊긴다 — 서버 코드나 마이그레이션을
   바꿨을 때만 재기동하고, 했다고 보고한다. `flutter analyze` 오류가 **남의 파일**에서 나면 고치지 말고 알린다
   (다른 세션이 쓰는 중일 수 있다).
6. **문서도 나눠 쓴다.**
   - `docs/07` §4 세션 로그 제목 앞에 태그: `### 2026-10-04 [포스트] — …`
   - `docs/09`는 **§0 표의 내 줄만** 고친다. 머리·나머지는 "그 외" 세션 몫이다.
   - 내 콘텐츠의 API·스키마·리소스가 바뀌면 `01`·`02`·`08`의 **해당 절만** 고친다.
7. **범위 밖 요청도 사용자가 시키면 한다.** 다만 *"그건 ○○ 세션 범위라 거기서 동시에 만지고 있을 수 있다"* 를 한 줄 알린다.
8. 푸시 전에 `git pull --ff-only origin main`. 안 되면(다른 기기와 갈라짐) **멈추고 사용자에게 알린다** —
   남의 변경이 섞인 작업 폴더에서 rebase·merge를 혼자 하지 않는다.

## 5. 모든 콘텐츠에 걸린 결정 (되돌리지 말 것)

- 🚨 **앱은 세로 고정**(2026-10-05) — 폰을 눕혀도 돌지 않는다. `main.dart`(`setPreferredOrientations`) +
  `AndroidManifest.xml`(`screenOrientation="portrait"`) + iOS `Info.plist` 세 곳이 함께 막는다. 가로 레이아웃은 만들지 않는다
- 🚨 **댓글 규칙**(사용자 확정 2026-10-11) — **포스트와 달빛 한마디 공통**. 정본은 `docs/01` §댓글 표.
  - **3단계까지**만. 3차 댓글은 답글 대상으로 고를 수 없다
  - **1차**: 게시자(포스트 주인·한마디 작성자)를 **뺀** 모든 사용자, 몇 번이든 — **게시자는 자기 글에 1차 댓글 금지**
  - **2차**(1차의 대댓글): **게시자만, 1차 하나당 1번** · **3차**(2차의 대댓글): **그 1차 댓글 쓴 사람만, 2차 하나당 1번**
  - ✅ **구현됨(2026-10-11, V30)** — 서버 `CommentService.resolveDepth`가 부모에 답글이 있으면 409 `COMMENT_ALREADY_REPLIED`, 동시에 두 번 들어온 요청은 DB 유니크 `uk_comments_parent(parent_id)`가 막는다(같은 409). 앱은 가든 `comments_sheet.dart`·한마디 `daily_detail_screen.dart`의 `_replyBlockedReason`이 미리 가리고 이유를 말한다 (⚠️ 앱 판정이 **두 파일에 한 벌씩** — 함께 고칠 것). 검증 `tools/verify/verify_comment_once.py`(17건).
  - → 한 댓글 아래 대화는 **게시자와 댓글 단 사람 둘이서 세 마디**(대댓글 최대 2개). 더 하려면 1차 댓글을 새로 단다
  - ⚠️ "게시자 1차 금지"는 서버 **호출부 두 곳**(`GardenService.addComment` · `DailyQuestionService.addComment`)에 따로 있다 — 한쪽만 바꾸지 말 것
